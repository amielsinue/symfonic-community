# symfonic community

This is the public home for people who use [symfonic-core](https://core.symfonic.dev),
the Agent Graph Framework. The source code lives elsewhere; this repository holds
the conversation around it.

## Where to go

| I want to... | Go here |
|---|---|
| Ask how to do something | [Discussions: Q&A](https://github.com/amielsinue/symfonic-community/discussions/categories/q-a) |
| Propose an idea or a change | [Discussions: Ideas](https://github.com/amielsinue/symfonic-community/discussions/categories/ideas) |
| Show what you built | [Discussions: Show and tell](https://github.com/amielsinue/symfonic-community/discussions/categories/show-and-tell) |
| Report a bug | [New issue: bug report](https://github.com/amielsinue/symfonic-community/issues/new?template=bug_report.yml) |
| Request a concrete feature | [New issue: feature request](https://github.com/amielsinue/symfonic-community/issues/new?template=feature_request.yml) |
| Read the documentation | [core.symfonic.dev](https://core.symfonic.dev) |

Not sure whether something is a bug? Start a Q&A discussion. It can become an
issue later.

## Versions

The public package on [PyPI](https://pypi.org/project/symfonic-core/) is the
9.12 line. The documentation site may describe newer releases that are not on
PyPI yet. When you report something, include the version you run:

```bash
python -c "import importlib.metadata as m; print(m.version('symfonic-core'))"
```

## How requests are handled

- Bugs and feature requests are read and triaged by the maintainers.
- An accepted request is tracked internally and linked back here when it ships.
- Not every idea will be built. When one is declined, the issue says why.

See [CONTRIBUTING.md](CONTRIBUTING.md) for what makes a report easy to act on.

## Ground rules

Be kind, stay on topic, and assume good intent. Do not post API keys,
credentials, or private data in issues, logs or code samples.
