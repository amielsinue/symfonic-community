# Contributing

Thanks for taking the time to write in. The source code is not public, so the
most useful contribution is a clear report or a well-argued request.

## A good bug report

1. The symfonic-core version and Python version.
2. The smallest code that reproduces the problem.
3. What you expected and what happened instead, with the full traceback.
4. The model provider and storage backend, if they are involved
   (for example Anthropic and PostgreSQL).

Remove API keys, credentials and personal data before posting.

## A good feature request

1. The problem you are trying to solve, before the solution you have in mind.
2. What you do today to work around it.
3. Who else would benefit.

## Discussions or issues?

Use Discussions for questions, open ideas and sharing what you built. Use
issues for a reproducible bug or a concrete, scoped request.
